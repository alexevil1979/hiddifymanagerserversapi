Обзор

Роль

DevOps-агент по парку VPS с Hiddify Manager: create → install → configure → restore → verify. Работа идемпотентна.

Жёсткие правила

  • Только 12.3.3, не release.
  • Без «переустанови» не ставить поверх другой версии.
  • Секреты только из env / .env / чата, не в git.
  • Домены только из domains.yml.

SSH и доступ

Способы из inventory

  • auth.method: password — пароль из env password_env, вход через plink.
  • auth.method: key — ключ из key_path_env (OpenSSH).
  • auth.method: agent — только явный agent, без подбора чужих ключей.

Особые порты

vpn-vp6 — SSH на :22022, не 22.

Jump / SOCKS (vp2 и изоляция)

Прямой SSH на 150.241.86.99 с агента часто timeout. Рабочий путь:

  1. SSH на 192.168.1.152 (как в telegram.local.json).
  2. Локальные SOCKS на jump: 127.0.0.1:1080–1085 (снаружи LAN закрыты).
  3. На vp2:22 реально ходят 1084 и 1085.
  4. Хелперы на jump: /tmp/vp2-ssh.sh, /tmp/vp2-scp.sh (sshpass + nc -X 5).
ProxyCommand: nc -X 5 -x 127.0.0.1:1084 %h %p
sshpass -e ssh -o ProxyCommand="…" root@150.241.86.99
Hostkey: после переустановки ОС ключ хоста меняется. plink -batch без accept падает — нужен новый hostkey или одноразовый accept. OpenSSH: StrictHostKeyChecking=accept-new.

Пайплайн «с нуля» (образец)

  1. Ubuntu 22.04 jammy, SSH способом из карточки.
  2. scripts/install-hiddify.sh → строго 12.3.3.
  3. Lock: auto_update=false, package_mode=v12.3.3, admin_lang/lang=ru, country=other, first_setup=false.
  4. Пароль владельца из HIDDIFY_ADMIN_PASSWORD.
  5. DNS A-записи {subdomain}.{зона} на все зоны из cloudflare_zones.
  6. Профиль из samples/protocols.json + домены (direct или cdn).
  7. apply_configs.sh (иногда дважды).
  8. Restore users/admins + proxy paths из бэкапа этой машины.
  9. Проверки: dashboard не quick-setup, API status, подписка не пустая.

Если на диске уже не 12.3.3 — стоп, пока пользователь не скажет «переустанови».

Restore users / admins / paths

Скрипт scripts/restore-users-admins.sh. Восстанавливает только:

  • admin_users + users
  • path-ключи: proxy_path, proxy_path_admin, proxy_path_client

Не тащит домены, протоколы, private keys, package_mode=release.

После restore путей нужен полный apply_configs.sh, иначе HAProxy maps остаются со старыми path → админка 400/DECOY. Иногда hconfig() читает кэш Redis: перезапуск hiddify-redis + hiddify-panel выравнивает значение.

Админ-URL: https://{domain}/{proxy_path_admin}/{admin_uuid}/

DNS: direct vs CDN

direct (по умолчанию)

  • Cloudflare A-запись, proxied: false (DNS only).
  • В панели: DomainType.direct.
  • Сертификат origin через acme на самом VPS.

cdn (vp2)

  • Cloudflare A-запись, proxied: true (оранжевое облако).
  • В панели: DomainType.cdn.
  • В inventory: desired.domain_modes: [cdn].
  • Админка через CDN работает с UUID в path.

Зоны: sdfsdfsdfsd.store, losttv.site, linkusers3.online. Токен: CLOUDFLARE_API_TOKEN.

BS-пара (bridge/exit)

  • console1 (ru) — whitelist entry, WG клиент к exit.
  • vp16 (eu) — exit, WG 10.88.88.0/24 :51888, Reality, sockopt freedom → wg-bs-exit.

Артефакты: artifacts/bs-pair/ (ключи публичные, setup/fix скрипты). Подробности также в docs fullvpnservice (вне репо).

HAProxy maps / PhoneRadar

Симптом: после restore путей админка отдаёт decoy/400, CRM «не тот path».

  1. Убедиться, что в БД paths = из бэкапа.
  2. Полный apply_configs.sh.
  3. systemctl restart hiddify-haproxy (юнит может называться haproxy или hiddify-haproxy).
  4. Проверить maps: /opt/hiddify-manager/haproxy/maps/path* содержат нужный admin path.

Грабли (зафиксировано)

  • Канал release уводит панель с 12.3.3 → всегда pin + auto_update=false.
  • first_setup=true → вечный Quick Setup в UI.
  • Restore без path → ломаются CRM/подписки.
  • Hostkey mismatch после OS reinstall.
  • vp2: прямой :22 недоступен; SOCKS только localhost на .152; рабочие порты 1084/1085.
  • CDN без UUID в URL → 400 invalid request; с UUID → 200.
  • hconfig vs StrConfig: после path restore сверять Redis/panel restart.
  • Диск 92%+ на старом vp2 мешал; после OS reinstall — ок.
  • Не открывать тысячи SSH разом на выборке.
