Подробная инструкция: сборка по образцу

Как довести один VPS до эталона парка: Hiddify 12.3.3, DNS, протоколы из samples, опциональный restore users/paths. Markdown-копия: docs/obrazec-sborka.md.

образец install DNS профиль restore проверки

0. Что считается «образцом»

ОСUbuntu 22.04 jammy
Hiddify12.3.3 (v12.3.3), не канал release
auto_updatefalse
package_modev12.3.3
admin_lang / langru
countryother
first_setupfalse
Протоколытолько samples/protocols.json
Доменызоны из domains.yml, метка subdomain
Режим доменаобычно direct; CDN → cdn + CF proxied
Пароль владельцаHIDDIFY_ADMIN_PASSWORD
Usersне плодить «на всякий»; restore из бэкапа этой машины
Полный дамп чужой панели не источник протоколов и доменов.

1. Входные данные

  1. Селектор inventory: id (пример vpn-vp2). Без селектора на парк не идти.
  2. Карточка: host, SSH, subdomain, cloudflare_zones, desired.domain_modes.
  3. Локальный .env: SSH-секрет, CLOUDFLARE_API_TOKEN, HIDDIFY_ADMIN_PASSWORD.
  4. Для restore: бэкап в backups/<id>/ с admin_users, users и тремя path в hconfigs.

2. Предусловия

. /etc/os-release && echo "$VERSION_CODENAME"   # jammy
test -f /opt/hiddify-manager/VERSION && cat /opt/hiddify-manager/VERSION || echo NO_HIDDIFY
ФактДействие
Нет Hiddifyставить §3
VERSION=12.3.3не переустанавливать; DNS/профиль при необходимости
Другая версиястоп, пока не скажут «переустанови»
Нет SSHчинить доступ (порт / пароль / SOCKS)

Особые доступы: vpn-vp6 порт 22022; vpn-vp2 — jump 192.168.1.152 + SOCKS 1084/1085.

3. Установка Hiddify 12.3.3

Только scripts/install-hiddify.sh (идемпотентен). Заливать с LF.

scp scripts/install-hiddify.sh root@HOST:/tmp/install-hiddify.sh
ssh root@HOST 'sed -i "s/\r$//" /tmp/install-hiddify.sh && chmod 700 /tmp/install-hiddify.sh
setsid bash /tmp/install-hiddify.sh > /var/log/hiddify-install.log 2>&1 < /dev/null &
echo $! > /var/log/hiddify-install.pid'

Скрипт: apt upgrade → sysctl IPv6 off → swap → HAProxy 3.0 hold → download v12.3.3 → lock_panel.

Успех: в логе Hiddify 12.3.3 installed, файл /opt/hiddify-manager/VERSION = 12.3.3.

Пароль владельца — из HIDDIFY_ADMIN_PASSWORD (отдельно или через restore).

4. DNS (Cloudflare)

Зоны: sdfsdfsdfsd.store, losttv.site, linkusers3.online.

direct

A → host, proxied: false. В панели DomainType.direct.

cdn

A → host, proxied: true. В панели DomainType.cdn. Inventory: domain_modes: [cdn].

Токен CLOUDFLARE_API_TOKEN. Пустой subdomain — DNS не трогать. Корень зоны не занимать.

5. Профиль: домены + протоколы

  1. Бэкап панели.
  2. Залить /tmp/protocols.json из samples/protocols.json.
  3. Добавить IP + домены {subdomain}.* (direct или cdn).
  4. Применить hconfigs/proxies из JSON; снова lock-поля и first_setup=false.
  5. Снять в inventory: admin_uuid, paths.
  6. apply_configs.sh --no-gui --no-log (при сомнении — дважды).
  7. Ещё раз first_setup=false.

6. Restore users / admins / paths

Только после свежей установки этой же сессии, когда установщик напечатал Hiddify 12.3.3 installed. Если панель уже стояла, restore не запускать, пока старый /opt/hiddify-manager не убран и установка не прошла заново.

export BACKUP_JSON=/tmp/restore-users.json
export ADMIN_PASS_FILE=/tmp/admin.pass
export SERVER_ID=vpn-vpN
bash /tmp/restore-users-admins.sh

Восстанавливает только users/admins + три path, затем apply-users и полный apply. Не делать полный set_settings=True.

После path restore при 400/decoy: проверить paths в БД, restart redis/panel, повторный apply_configs, restart haproxy, сверить maps в /opt/hiddify-manager/haproxy/maps/path*.

Админ-URL: https://{domain}/{proxy_path_admin}/{admin_uuid}/

7. Проверки

  • VERSION = 12.3.3, auto_update=false, package_mode=v12.3.3, first_setup=false
  • UI — dashboard, не Quick Setup
  • API …/api/v2/admin/server_status/ + Hiddify-API-Key → 200
  • DNS резолвится в host; CDN — proxied
  • CDN: без UUID часто 400; с UUID — 200
  • Подписка не пустая (если был restore)
  • Inventory: state: configured

9. Чего не делать

  • Канал release / свежая версия поверх 12.3.3
  • Установка поверх другой версии без «переустанови»
  • Протоколы/домены из чужого полного бэкапа
  • Смена SSH ОС без задачи; массовые юзеры «на всякий»
  • Секреты и полные admin URL в git/docs
